# Python依存をなくすC#移行実装計画

作成日: 2026-10-11
状態: C#実装とPython撤去を実装済み。最終検証の記録は [csharp-migration.md](csharp-migration.md) を参照。
本書の本文は実装開始時の方針を残し、チェック欄で完了状況を示す。
検証対象: ユーザー指示によりLinuxのみ。Windows検証は不要。

## 1. 目的と実装開始時の前提

COBOLの解析・変換、生成プログラムの実行、回帰テスト、公開コーパスの検証、デモ準備を.NETだけで行えるようにする。Pythonを別途インストールする必要がない配布物と開発環境を完成形とする。

現在の実行準備機能のPR #8をマージした後、そのマージを含むmainから別ブランチを作る。マージコミットと利用ツールのバージョンを基準記録に残す。PR #8のマージ自体はこの計画の実装作業に含めない。未マージなら基準確定前に移植を開始しない。

本書のプロジェクト名・新設コマンドは実装開始時の設計案。実現した構成と利用コマンドは [開発手順](development.md) と [移行記録](csharp-migration.md) を参照。

## 2. 完成の定義

- [x] 製品CLIがPythonプロセスを起動せず、C#解析器を直接呼び出す。
- [x] 解析・変換・生成物のビルド／実行・adoptがPython未導入環境で動く。
- [x] 開発・CI・テスト・デモ・コーパス操作にもPythonを要求しない。
- [x] 既存の対応範囲、診断、未対応文のstub化、生成物の編集／削除保護を維持する。
- [x] Linuxで検証し、改行・パス・文字列処理の差異を解消する。
- [x] 全回帰検査と固定コーパス検証が成功し、Python版との差異に未説明のものがない。
- [x] 配布物からPythonコード・Python起動設定を除去し、必要なライセンス・由来の記録を保持する。
- [x] README、CLI説明、CI、再現手順を.NETのみの手順に更新する。

移植と同時にCOBOLの対応範囲を広げたり、未検証のホスト互換性を主張したりしない。既存不具合を発見した場合は差分を記録し、互換移植と分離して修正・期待値変更をレビューする。Python版との一致だけでCOBOL仕様への正しさを証明したとは扱わない。

## 4. 設計方針と互換性

### 4.1 プロジェクト構成

- `src/CobolCS.Frontend`: 設定、入力処理、解析、診断、IR構築を担当するライブラリ。
- `src/CobolCS.Cli`: 既存コマンドを保ち、解析ライブラリを直接呼ぶ。
- `tests/CobolCS.Frontend.Tests`: 解析の単体・境界・差分検査。
- `tests/CobolCS.IntegrationTests`: CLI、生成C#、再生成、adopt等の統合検査。
- `tools/CobolCS.Tools`: 開発用コーパス操作、集計、デモ準備。製品CLIには混在させない。

テストは.NETの標準的なテスト実行に統合し、生成テストと同様にMSTestを候補とする。既存のランタイム検査は維持する。既存の警告エラー化・StyleCop規約を適用する。

### 4.2 IR境界を維持する

現在のIRは`schemaVersion: 2.2`、`frontendVersion: 0.2.2`を出力している。開始時に再確認する。初期移植ではこのIRの項目名・意味・配列順序・識別子を維持し、既存Generatorへ接続する。内部型を導入しても、IR全体の再設計を同時に行わない。

`frontendVersion`や実装由来を示す項目は実態に合わせる。互換性のためにPython実装を名乗らせない。変更するメタデータは明示し、生成物・ハッシュへの影響を検証する。`upstreamCommit`等の由来情報は用途を確認して維持または明示的に移行する。

### 4.3 差分比較の規則

同一入力・設定・COPY探索順・動作モードで両解析器を実行し、JSONを構造比較する。

- オブジェクトのキー順は構造比較では無視できるが、ハッシュ計算に使うシリアライズは別途互換性を検査する。
- 配列順、数値の十進文字列表現、nullと欠落、空配列、診断の重大度・位置、symbol／statement IDは保持する。
- 絶対作業ディレクトリ等を正規化する必要がある場合は、対象フィールドと理由を限定して記録する。文字列全体の無条件置換はしない。
- 実装バージョン等の意図した差異は、項目単位の許可リストと理由で管理する。差分全体を無視する仕組みにしない。
- 比較結果は入力ID、JSONパス、期待値、実際値を記録する。決定性も別に確認する。

重点確認事項はUTF-8バイト位置、Unicodeの列位置、日本語識別子、大小文字変換、Python／.NETの正規表現差、CRLF／LF、固定形式の列、COPYスタック、パス比較・列挙順、JSONエスケープ、設定ハッシュである。C#のUTF-16文字数をPythonの文字数と同一視しない。

## 7. 検証手順と記録

既存の実行可能な共通チェック:

```bash
dotnet build CobolCS.sln -m:1
dotnet format whitespace CobolCS.sln --verify-no-changes --no-restore
dotnet run --project tests/CobolCS.Tests --no-build
git diff --check
```

新設後の想定チェック:

```bash
dotnet test tests/CobolCS.Frontend.Tests
dotnet test tests/CobolCS.IntegrationTests
```

コーパス用C#ツールのコマンドは段階5で確定し、既存操作からの対応表と実行例をREADMEに掲載する。固定済みのcourse／fun／bank／carddemo／db2を同じlockで測定する。開始時点の参考値は171本のビルド、独立期待値との実行一致3件である。171本すべての業務実行成功を意味しない。基準値はマージ後に再確定する。

検証結果には以下を残す:

- 基準／移植後コミット、比較時のソースハッシュ、OS、SDK、移行中のみPythonバージョン。
- 実行コマンド、終了コード、テスト結果、比較件数、未解決差分。
- 許可した差異のJSONパスと理由、生成物・編集保護への影響。
- コーパスの取得元・lock・checksumと集計結果。
- Python未導入の確認方法、配布物一覧、Linuxの結果。

既存の検証記録を移植後の結果で上書きしない。新しい記録として保存する。Python版の期待値をC#版の出力で自動更新しない。Linux CIでは実際の生成物ビルドを実行し、CRLF由来の問題を確認する。

## 8. PR分割と進行規則

| PR案 | 範囲 | 依存 |
| --- | --- | --- |
| A | 基準記録、比較基盤、Frontendライブラリの土台 | 現在のPR #8のマージ |
| B | 設定・ソース・COPY・PIC・宣言 | A |
| C | 式・手続き・文・依存情報・完全IR比較 | B |
| D | CLI切り替え、配布依存除去、旧生成物互換性 | C |
| E | 回帰テスト・補助ツール・CI移植、Python撤去 | D |

CやEが大きくなる場合は機能単位でさらに分割する。各PRで比較可能な範囲と未完了範囲を明記し、途中のC#解析器を既定にしない。C#への切り替え前は既存製品経路を保ち、切り替え後の不具合をPythonへの黙ったフォールバックで隠さない。

実装担当は前段階の完了条件を満たしたら次段階へ進む。コード作成だけ、解析比較だけで全体完了としない。PR作成・push・マージは、その時点のユーザー指示に従う。本書自体はマージや公開の承認ではない。
